## Gotchas

- **Never emit an SDK snippet without compiling it against the consumer's PINNED tag AND master** — write the snippet to a scratch module, `go.mod`-require the pinned version (or `replace` to the local tree for master), `go build`, THEN paste; prefer version-neutral constructs (`token != ""`) over newest-type idioms when consumers pin older tags. The md-go-snippets gate only PARSES blocks — wrong identifiers survive it; scratch-compiling is the identifier-level gate. Origin (fabricated `transfer.SourceValue`/`TargetValue` cost bank-sync months; `TwoFAApprovalToken().IsZero()` master-only): bank-sync's AGENTS + `docs/reviews/2026-10-16_agents-incident-narratives.md`. Standing facts: error-system snippets compile on v0.15.0+ ONLY; bank-sync (pinned v0.14.0) compiles UNMODIFIED against the v0.15.0 tree — when it bumps, point it at the `docs/error-codes.md` recipe and sweep its `errors.AsType`-only handling for sentinels.
- **Outgoing query timestamps must be UTC `Z`** — Wise rejects zone-offset timestamps (`+02:00`) with HTTP 422 `wrong.date.format`. All outgoing query timestamps go through `formatWiseTimestamp` (`helpers.go`). Never format `time.Time` directly into query params. (Live cost of breaking this: ~2.5 days of failing bank-sync transfers, fixed v0.8.1.)
- **SCA 403s have an empty body** — SCA-protected endpoints (balance statements for UK/EEA profiles) answer HTTP 403 with NO body; verdict + one-time token live in `x-2fa-approval-result` / `x-2fa-approval` headers. Classified `*SCAChallengeError` (not `*AuthError`); `TwoFAApprovalToken()` extracts the OTT, `WithSCAApprovalToken` completes the challenge, the `ott.go` endpoints clear challenges programmatically. **The OTT is the distinct type `OneTimeToken`**: every OTT-taking signature is typed so an OTT cannot stand where an OTP code or API key belongs; `OTTStatus.ActionType` is the `OTTAction` open enum; a tokenless PSD2 challenge yields the zero `OneTimeToken` (pinned by `TestCheckErrorTokenlessSCAChallenge`). **The OTT value never appears in an error string or log** — `SCAChallengeError.Error()` reports only `token issued: true/false`. Challenge types are UPPERCASE (SMS/WHATSAPP/VOICE), endpoint paths lowercase — `OTTChannel.challengeType()` is the single mapping. Data-model review: `docs/reviews/2026-10-16_sca-auth-data-model.html`.
- **Inconsistent timestamp formats** — Wise emits: full RFC3339, zoneless `T`-separated (live `/v2/profiles` `createdAt`), space-separated statement dates, millis+numeric-zone delivery estimates, and no-millis numeric-zone rate timestamps (`/v1/rates` `time`). One tolerant parser (`parseWiseTimestamp`) handles all; zoneless = UTC. Never parse with a single strict layout.
- **Transaction.Date is UTC** — Wise statement dates (`"2006-01-02 15:04:05"`) carry no timezone; `parseWiseDate` reads them as UTC. Callers comparing to local-time values must convert explicitly (off-by-one-day risk at boundaries).
- **Amount vs Total** — `Transaction.Amount.Cents` is absolute value (always positive); `Transaction.Total.Cents` preserves sign (negative for debits). Both are `Money` fields. Getting this wrong silently produces wrong data.
- **CARD_PAYMENT vs CARD_REFUND classification** — `CARD_PAYMENT` always maps to `TransactionTypeCard` regardless of amount sign. Only `CARD_REFUND` is amount-dependent (positive → `TransactionTypeRefund`, non-positive → `TransactionTypeCard`). Do not re-group into one case branch — the README contract requires separate handling.
- **Balance filtering** — `ListBalances` silently drops `Visible: false` and invested balances; `GetBalance` does NOT filter. The live v4 endpoint requires `?types=STANDARD,SAVINGS` (sent via `balanceTypesQuery`); a bare path 400s `query.types: NotNull`. Public `BalanceType` is lowercase, wire UPPERCASE — convert via `balanceTypeWire`/`parseBalanceType`.
- **Sandbox URL migrated to V2** — sandbox is `api.wise-sandbox.com` since Nov 2025 (V1 deprecated June 30, 2026; V1 data after April 1, 2025 NOT migrated). `SandboxURL` tracks this.
- **Sandbox lane facts (live pass 2026-10-17)** — credentialed live tests read `WISE_SANDBOX_API_KEY` (mirrored at `~/.secrets/wise-sandbox.key`, mode 600, NEVER inside the repo). In sandbox, statements (CSV + JSON, personal AND business) are SCA-gated with SIGNATURE-type challenges: empty `ViewData`, no phone alternatives, `TriggerOTT(sms)` 404s `ott_challenge_not_found` — clearing needs the web flow (catch-all `111111`). Balance creation WORKS (standard + savings); identical `X-idempotence-uuid` replay returns the already-created balance. Quarterly-surface probing discriminates by body shape, not status code (see the "Webhook endpoints live on the quarterly versioned surface" entry). Two live-only wire shapes: top-level-`code`-only error envelope without `errors[]` (`non.existing.balance`, renders via `APIError.Message`) and funding-404s served `application/json` (spec's text/plain covers domain funding errors only). Treat single-probe 403 verdicts as provisional — re-verify before recording them.
- **Global headers (Apr 2026)** — `X-External-Correlation-Id` (supported via `WithCorrelationID`) and `x-trace-id` (intermediary-set, not client-set) are documented on all operations.
- **Retry-After + X-Rate-Limited-By headers (Apr 2026)** — 429s carry the rate-limit scope in `X-Rate-Limited-By` and `Retry-After`; `RateLimitError.RetryAfter` (delta-seconds or HTTP-date, fallback 1s) and `RateLimitedBy` capture them.
- **`//nolint:bodyclose`** — `getWithQuery` intentionally defers body close via `responseCloser`: the response outlives the helper, so the caller closes it. Don't remove it.
- **Two-layer type design** — raw structs (`internal/raw/types.go`) intentionally use wire primitives; public types (`types.go`) convert to branded IDs, enums, `time.Time`, `Money`. Raw types are consumer-invisible. The raw/public `TransferRequirement` mirror pair (both-site `// art-dupl:accept` directives) is the accepted price of tag-free public types — do NOT merge via type aliases (aliases would leak wire JSON tags into the public serialization surface).
- **art-dupl suppression is in-source directives** — `// art-dupl:accept <rationale>` comments ARE the config (no baseline file). Gate `-t 2 --type-aware`: 0 actionable / exit 0 (27 groups 2026-10-24, all accepted). - **Quote IDs are UUID strings** — unlike the int64 entity IDs, quote IDs are UUIDs: `QuoteID` is `id.ID[QuoteBrand, string]`, constructed with `NewQuoteID("...")`.
- **Recipient `details` is polymorphic** — required fields depend on currency and route (`sortCode`+`accountNumber` for GBP, `iban` for many EUR corridors). `Recipient.Details`/`CreateRecipientRequest.Details` stay `map[string]string` BY DECISION (spike 2026-10-31: `docs/planning/2026-10-31_12-28_typed-details-spike.md` — typed structs would promise what the server owns); callers discover fields via the account-requirements endpoints.
- **Transfer creation requires `customerTransactionId`** — this UUID is mandatory for idempotency; reusing it with the same `quoteUuid` + `targetAccount` returns the existing transfer instead of creating a duplicate.
- **Branded IDs are the public API** — every client method taking an ID uses branded types; construct with `NewProfileID`/`NewBalanceID`/…, unwrap with `.Get()`. Mixing entity IDs is a compile-time error.
- **No pagination** — Wise returns all transactions in a single response (`HasMore` removed in v0.4.0).
- **ListTransactions validates before calling the API** — empty currency or `From > To` returns an `errorfamily.Rejection` immediately, no network round-trip.

DevShells, the go-standard check phase, and .golangci.yml build-tags are configured; BuildFlow sets the var for its own tool subprocesses. `go env -w` does NOT work (home-manager symlinks `~/.config/go/env` read-only); plain shells are covered by the tracked `.envrc` (`use flake` + `use_go_env`; un-ignored via `!.envrc`) — do not "clean up" the negation.

## Conventions

- **Health probes: two, by design** — `Health` is the readiness probe (authenticated `ListProfiles` through the retry executor; worst case 4 attempts x 30 s + honored Retry-After waits); `VerifyCredentials` is the fail-fast credential check (single round-trip, retry ladder disabled, same typed errors; added 2026-10-31 per memo D2-b). No `HealthCheck` alias (the two-line `do.HealthcheckerWithContext` adapter is the whole cost); samber/do itself is deliberately absent — no DI container inside a library (ADR 002/003; recheck index: `docs/architecture-understanding/README.md`).
- **Webhook endpoints live on the quarterly versioned surface** — subscription CRUD uses `webhookSubscriptionsAPIVersion = "2027Q1"`, OTT uses `ottAPIVersion = "2027Q1"` (both `client.go`; both canonicalized from 2026Q4 on 2026-10-31 per the spec's server URL — credentialed sandbox probe: app-level bodies on 2026Q4+2027Q1, router-404 on 2027Q2), NOT legacy `/v1../v4`; the two families roll over INDEPENDENTLY. Webhook wire is snake_case JSON (unlike the camelCase core) — tagliatelle is path-excluded for `internal/raw/webhooks.go` (a nolint above `package` becomes a second package doc — use the exclusions rule). The envelope keeps undecoded payload bytes in a `jsontext.Value` (json/v2-native; never re-marshal to read). Subscription IDs are UUID strings (`WebhookSubscriptionID`). Rollover probing discriminates by BODY SHAPE, not status: with a sandbox key, served prefixes answer app-level `{"code":"ott_not_found"}`/`{"error":"unauthorized"}` while unknown ones answer router-level `{"error":"Not Found"}`. `TestQuarterlyAPIVersionsConsistent` pins every quarter-qualified path literal (code + mocks + README) to the constants — flip the constant, then fix every site it lists.
- **`Accept-Minor-Version: 1` on account-requirements** — minor version 1 includes recipient name/email fields and is what Wise recommends for new integrations. Always sent on those endpoints via the `extraHeaders` hook (see `quotes.go`), never via `setHeaders`. Any future account-requirements endpoint sends the same header.
- **Error catalog is central** (`errors.go`) — every error code the SDK emits is a named constant there (call sites reference constants; tests pin wire values as literals — do NOT sed test files when renaming). The four response-shape sentinels (`ErrEmptyRateList`, `ErrAccountIdentificationCardinality`, `ErrOTTAlternativesShape`, `ErrTransferRefundAmountMissing`) are EXPORTED, declared with the `error` interface type (type elision silently breaks sentinel matching; `TestSentinelsStayInterfaceTyped` guards the shape), always returned wrapped, consumer-matchable via `errors.Is`. New codes/sentinels go into errors.go AND the `TestErrorCodesUniqueAndWellFormed` list. `fetchByID` takes the named invalid-request code — never reassemble `"wise."+resource+…` at runtime.
- **Error-system matching contract** (`errors.go`, v0.15.0) — `newAPIError` keeps Wise's structured envelope in `APIError.Details []WiseErrorDetail` (wire order; `Message` is the flattened join, pinned by fuzz). Two COMPLEMENTARY idioms, split pinned by `TestAsTypeAndIsAreComplementary`: **types via `errors.AsType`** (status, RetryAfter, token); **curated codes via `errors.Is`** — `APIError.Is` compares `Details` codes against the `codeSentinels` map ONLY and is promoted through every embedding subtype (matches through any wrap chain); **any other code via `APIError.HasCode(WiseErrorCode)`** (open enum). Wave-1 = the 11 branching-story codes (`TestCodeSentinelsMapCuratedCodes` pins the map at 11 — wave-2 needs a conscious pin update). Status drives the TYPE, body code drives the MATCH. End-to-end pin: `TestErrorSurfaceMappingMatrix`; reference: `docs/error-codes.md`. **`errors.AsType` does NOT descend into embedded fields** (subtypes have no `Unwrap`): `AsType[*APIError]` matches only bare-APIError statuses — NEVER write docs claiming otherwise. `gochecknoglobals` on `codeSentinels` suppressed with rationale.
- **Error handling** — domain error types implement `go-error-family` interfaces (`ErrorCode`, `ErrorFamily`, `ErrorContext`, `IsRetryable`). Call-site wrapping is `fmt.Errorf("context: %w", err)` — anonymous by design; the inner error carries name + classification. `errorfamily.WrapCorruption` for response decode failures; `errorfamily.NewRejection` for not-found + client-side validation.
- **Error-context convention** — every error type exposes `ErrorContext()`. `APIError` pins `status_code` + first granular code as `wise_code`; `RateLimitError` adds `retry_after`/`rate_limited_by`; `SCAChallengeError` adds `approval_result`/`approval_token_issued` (bools, never the raw OTT). The other four types deliberately have NO override (pinned by `TestErrorContexts`). ONLY `RateLimitError`/`ServerError` implement `IsRetryable` (pinned by `TestIsRetryableContract`). Mapper/validation messages carry the raw wire input; unreadable bodies surface as `"(response body could not be read: …)"`.
- **Validation idiom is exactly two forms, deliberately** — `requireID` for branded IDs (zero/empty → Rejection), inline checks for everything else. A generic `requireNonEmpty` helper was DECLINED (2026-09-13): non-ID validations differ in predicate, wire field name, and message shape. Do not introduce a third form.
- **Error types** — `newAPIError()` in `errors.go` handles all status-code-to-type mapping. Never construct `AuthError`/`NotFoundError` etc. directly outside that function.
- **`newAPIError` takes a `string` body and returns `error`** — in tests construct `&APIError{...}`/`&RateLimitError{...}` directly.
- **Error families** — `APIError`/`AuthError`/`NotFoundError` → Rejection (not retryable); `RateLimitError`/`ServerError` → Transient (retryable).
- **`requireID` for every branded-ID guard** — zero/empty branded-ID validations go through `requireID` (`ids.go`); it checks `ID.IsZero()`, covering int64 IDs and string `QuoteID` alike. Never hand-roll `x.Get() == 0 { NewRejection(...) }` blocks; non-ID validations stay inline.
- **`toTransfer` wraps raw transfer mapping** — GetTransfer/CreateTransfer/CancelTransfer map via `toTransfer(label, transfer)` (`transfers.go`); the label is the error-message prefix, pinned by tests.
- **Details wire keys have one spelling** — `CreateTransferRequest.detailsWire()` delegates to `TransferRequirementsDetails.toWire()`. New details fields belong on `TransferRequirementsDetails` first; mirror onto `CreateTransferRequest` only if the create endpoint accepts them.
- **Every error type has its own `ErrorCode()`** — `wise.api_error`, `wise.rate_limit`, `wise.auth`, `wise.not_found`, `wise.server`.
- **`Money` is a value object, NOT a math library** — all amounts are `Money{Cents int64, Currency Currency}` (ADR 001: `docs/adr/001-money-value-object-no-arithmetic.md`), pairing cents with currency so mismatched amounts are unrepresentable. Deliberately no `Add`/`Sub`/`IsZero`/`IsNegative`/`Equal` — the SDK is an anti-corruption layer; arithmetic is the consumer's domain. `Currency` is a typed string validated by `NewCurrency` (3-letter uppercase ASCII); `wise.Currency("EUR")` constructs directly. `ListTransactionsRequest.Currency` is `Currency`. `toMoney` (`helpers.go`) converts `raw.BalanceAmount` with currency validation.
- **`DetailType` typed enum** — `ListTransactionsRequest.Type` is `DetailType` (not `string`) since v0.5.0; use `wise.DetailTypeCardPayment`, not `"CARD_PAYMENT"`.
- **`setHeaders`** — sets `Authorization`, `X-External-Correlation-Id` (client-wide + ctx override via `WithRequestCorrelationID`; ctx wins), and the SCA approval token. Add new headers here, not per-endpoint. Endpoint-specific negotiation headers go through the `extraHeaders` hook; raw responses through `getRaw`.
- **Retry exhaustion preserves typed errors** — the executor is go-retry (ADR 003): on exhaustion the `ErrExhausted` chain carries the final attempt's typed error via `WithCause`, so `errors.AsType` reaches `*RateLimitError`/`*ServerError` with no unwrap bridge. `executeWithLogging` classifies each attempt's non-2xx via `checkError`; that typed error drives `isRetryableError` and the `DelayFunc` Retry-After honoring (capped at `WithRetry`'s max delay; go-retry counts TOTAL attempts — `MaxAttempts = maxRetries + 1`). The `DelayFunc` also emits one delay-decision entry through the SAME `LogRequest` channel (`Status: 429`, honored wait in `RetryAfterDelay`, `Method`/`URL` empty). Locked by the 429 BDD tests + the 2026-10-31 deadline-abort contexts; do not regress.
- **OTEL surface = the two hooks, never a telemetry dependency** — spans via `WithHTTPClient` + `otelhttp.NewTransport`; metrics via a `WithLogger`→otel-meter bridge that MUST skip `RetryAfterDelay > 0` entries (delay decisions are not exchanges). Recipe verified end-to-end 2026-10-19 on master AND pinned v0.16.0 (README "Observability → OpenTelemetry"). `WithMetrics` on hold until a consumer need outgrows the bridge. Wise-side correlation stays `WithRequestCorrelationID`; `x-trace-id` is intermediary-set.
- **Go 1.26 `x509.MarshalPKIXPublicKey` returns `([]byte, error)`** — two-value signature; same for test helpers.
- **Spec-conformance gate** — `spec_conformance_test.go` validates every mock-harness exchange against the vendored OpenAPI 3.1 snapshot (`docs/reviews/wise-api-openapi.json`, kin-openapi legacy router); version-prefix stripping maps SDK wire paths onto unversioned templates. Exemptions: statement file formats, legacy bare-array `/v2/accounts`, per-exchange `exemptResponseSchema` for corrupt fixtures. `conformanceOptions()` goes to BOTH request and response validation; `date-time` deliberately permissive. Coverage guard is SHUFFLE-PROOF (`TestMain` asserts floors only post-suite via `conformanceSuiteCompleted`; a `-run` filter excluding the suite exits 0 by design). Floors: ≥25 templates / ≥60 exchanges / ≥4 statement variants; spec-sanity pins OpenAPI 3.1.0 + ≥150 paths. Statement `type` is `StatementType` (COMPACT|FLAT), NOT DetailType. `CreateBalance` must send `X-idempotence-uuid`. Funding errors are `text/plain`. Go named-return parameters SHADOW package variables of the same name — avoid same-named returns.
- **Wise 2027Q1 spec moved account-details (migrated in v0.14.0)** — the live spec removed `GET /profiles/{profileId}/account-details` and added `GET /balances/account-details/{id}` (same operationId); `GetBankAccountDetails` (`account_details.go`) calls the new path keyed by `AccountDetailsID`. The spec-drift check extracts every (method, path) the SDK calls from root *.go files (incl. wrapper indirections: `fetchByID`, `listTransfersPage`, `c.request` with `http.Method*` literals) and structural-matches them against the live spec — numeric `%d` params never match literal segments; the version-prefix strip covers `/%s/`-built quarterly prefixes; fetching the live spec needs a custom User-Agent. `nix run .#spec-drift` exit 0 against 2027Q1.
- **API docs study** — the Wise API has ~215 documented REST operations across 51 reference categories (per-endpoint coverage matrix — 46 shipped / 49 demand-gated / 123 out-of-scope — in `FEATURES.md` is THE endpoint inventory). The SDK covers 47 endpoint methods across 15 resource files (44 operation-carrying + the `ListProfiles` wrappers `Authenticate`/`Health`/`VerifyCredentials` + `ClearSCAChallenge`; growth lineage: CHANGELOG + `docs/releases/`; count gate-checked by `nix run .#doc-verify`). Denominator convention (harmonized 2026-10-31): **47 public `*Client` methods / 46 Wise operations shipped / 15 resource files** — "17 resource families" survives only as ROADMAP's enumerated family list; derive files with `ls *.go | grep -v _test | grep -vE '^(client|errors|helpers|ids|options|types)\.go$' | wc -l`. When adding endpoints, start from the machine-readable OpenAPI spec (`docs/reviews/wise-api-openapi.json`, authoritative for field types/optionality/ID formats; cross-check NEW endpoints against the live preview reference — `<category>.md`, `llms.txt`, sitemap). Smaller cross-check spec: `docs/reviews/wise-api-core-schemas.json`.
