# wise-go — AGENTS.md

## Gotchas

- **Never emit an SDK snippet without compiling it against the consumer's PINNED tag AND master** — write the snippet to a scratch module, `go.mod`-require the version the consumer actually pins, `go build`, THEN paste; prefer version-neutral constructs (`token != ""`) over newest-type idioms when consumers pin older tags. Origin: a fabricated snippet (invented `transfer.SourceValue`/`TargetValue`, 2026-10-16) cost bank-sync months of broken `GetTransfer`; same day, README's `TwoFAApprovalToken().IsZero()` compiled on master but not v0.13.0 (plain `string` there). The md-go-snippets gate only PARSES blocks — wrong identifiers survive it; this scratch-compile is the identifier-level gate (full 33-block sweep 2026-10-16 fixed the quick-start loop-scoped `balances` bug + a never-introduced `profile`). Error-system snippets (decision tree, sentinels, `HasCode`, bank-sync recipe) compile on v0.15.0+ ONLY (verified at the tag via clean-dir `go get`); bank-sync (pinned v0.14.0) compiles UNMODIFIED against the v0.15.0 tree (replace-compile 2026-10-17) — when it bumps, point it at the recipe and sweep its `errors.AsType`-only handling for sentinels.
- **Outgoing query timestamps must be UTC `Z`** — Wise rejects zone-offset timestamps (`+02:00`) with HTTP 422 `wrong.date.format`. All outgoing query timestamps go through `formatWiseTimestamp` (`helpers.go`). Live regression 2026-08-19..21: every bank-sync transfers call failed for ~2.5 days because `time.Now()` carried CEST (fixed in v0.8.1). Never format `time.Time` directly into query params.
- **SCA 403s have an empty body** — SCA-protected endpoints (balance statements for UK/EEA profiles) answer HTTP 403 with NO body; verdict + one-time token live in `x-2fa-approval-result` / `x-2fa-approval` headers. Classified `*SCAChallengeError` (not `*AuthError`); `TwoFAApprovalToken()` extracts the OTT, `WithSCAApprovalToken` completes the challenge, and the `ott.go` endpoints (`/2026Q3/one-time-token/...` via `ottAPIVersion`) clear challenges programmatically. **The OTT is the distinct type `OneTimeToken`** (2026-10-16 data-model review, `docs/reviews/2026-10-16_sca-auth-data-model.html`): every OTT-taking signature (GetOTTStatus/TriggerOTT/VerifyOTT/ClearSCAChallenge/WithSCAApprovalToken/TwoFAApprovalToken) is typed so an OTT cannot stand where an OTP code or API key belongs; `OTTStatus.ActionType` is the `OTTAction` open enum; a tokenless PSD2 challenge yields the zero `OneTimeToken` (pinned by `TestCheckErrorTokenlessSCAChallenge`). **The OTT value never appears in an error string or log** — `SCAChallengeError.Error()` reports only `token issued: true/false`. Challenge types are UPPERCASE (SMS/WHATSAPP/VOICE), endpoint paths lowercase — `OTTChannel.challengeType()` is the single mapping; never compare directly.
- **Inconsistent timestamp formats** — Wise emits: full RFC3339, zoneless `T`-separated (live `/v2/profiles` `createdAt`), space-separated statement dates, millis+numeric-zone delivery estimates, and no-millis numeric-zone rate timestamps (`/v1/rates` `time` — live regression 2026-10-07, killed bank-sync FX totals). One tolerant parser (`parseWiseTimestamp`) handles all; zoneless = UTC. Never parse with a single strict layout.
- **Amount vs Total** — `Transaction.Amount.Cents` is absolute value (always positive). `Transaction.Total.Cents` preserves sign (negative for debits). Getting this wrong silently produces wrong data. Both are `Money` fields (cents + currency paired).
- **CARD_PAYMENT vs CARD_REFUND classification** — `CARD_PAYMENT` always maps to `TransactionTypeCard` regardless of amount sign. Only `CARD_REFUND` is amount-dependent (positive → `TransactionTypeRefund`, non-positive → `TransactionTypeCard`). Do not re-group these into one case branch — the README contract requires separate handling.
- **Balance filtering** — `ListBalances` silently drops `Visible: false` and invested balances; `GetBalance` (direct per-balance endpoint) does NOT filter. The live v4 endpoint requires `?types=STANDARD,SAVINGS` (sent via `balanceTypesQuery`); a bare path 400s `query.types: NotNull`. Public `BalanceType` is lowercase, wire UPPERCASE — convert via `balanceTypeWire`/`parseBalanceType`.
- **Sandbox URL migrated to V2** — As of Nov 2025, Wise migrated sandbox from V1 (`api.sandbox.transferwise.tech`) to V2 (`api.wise-sandbox.com`). V1 was fully deprecated June 30, 2026. The SDK's `SandboxURL` constant was updated accordingly. Data created in V1 after April 1, 2025 was NOT migrated.
- **Global headers (Apr 2026)** — Wise documents `X-External-Correlation-Id` (distributed tracing) and `x-trace-id` on all operations. The SDK supports `X-External-Correlation-Id` via `WithCorrelationID`. The `x-trace-id` header is typically set by intermediaries, not clients.
- **Retry-After + X-Rate-Limited-By headers (Apr 2026)** — 429 responses include `X-Rate-Limited-By` identifying the rate-limit scope (e.g., "ip", "profile") and `Retry-After`. `RateLimitError.RetryAfter` is parsed from the HTTP `Retry-After` header (delta-seconds or HTTP-date), falling back to 1 second; `RateLimitError.RateLimitedBy` captures the scope.
- **`//nolint:bodyclose`** — `getWithQuery` intentionally defers body close via `responseCloser`: the response outlives the helper, so the caller closes it. Don't remove it.
- **Two-layer type design** — Raw structs (`internal/raw/types.go`) intentionally use wire primitives (`int64`/`string`/`float64`); the public types (`types.go`) convert to branded IDs, enums, `time.Time`, `Money`. Raw types are consumer-invisible. The raw/public `TransferRequirement` mirror pair (both-site `// art-dupl:accept` directives) is the accepted price of tag-free public types — do NOT merge via type aliases (aliases would leak Wise's wire JSON tags into the public serialization surface).
- **art-dupl suppression is in-source directives** — `// art-dupl:accept <rationale>` comments ARE the config (no baseline file, declined 2026-09-13). `-t 2 --type-aware` gate: 0 actionable, exit 0 — 25 groups at the v0.15.0 tag, all accepted (requireID-guard family, ownedByCustomer tails, bool predicates, raw/public mirror pairs with BOTH-SITES directives). Placement: declaration-level clones take a doc-comment directive; body-interior clones need it INSIDE the cloned range. POLICY not gate: warn-first CI job; run the CLI manually when touching cloned-adjacent code. History: `docs/reviews/2026-10-16_agents-incident-narratives.md`
- **Quote IDs are UUID strings** — Unlike profile/balance/transfer/recipient IDs, which are `int64`, Wise quote IDs are UUIDs (`string`). `QuoteID` is therefore `id.ID[QuoteBrand, string]` and constructed with `NewQuoteID("...")`.
- **Recipient `details` is polymorphic** — The required fields depend on currency and route (e.g. `sortCode`+`accountNumber` for GBP, `iban` for many EUR corridors). The SDK exposes `Recipient.Details` and `CreateRecipientRequest.Details` as `map[string]string`; callers must use the account-requirements endpoints to discover the exact fields for their corridor.
- **Transfer creation requires `customerTransactionId`** — This UUID is mandatory for idempotency. Reusing the same `customerTransactionId` with the same `quoteUuid` and `targetAccount` returns the existing transfer instead of creating a duplicate.
- **Branded IDs are the public API** — Every client method taking an ID uses branded types (`ListBalances(ctx, ProfileID)`, `GetBalance(ctx, ProfileID, BalanceID)`, `ListTransactionsRequest{ProfileID, BalanceID}`). Construct with `NewProfileID`/`NewBalanceID`/`NewTransactionID`; unwrap with `.Get()`. Mixing entity IDs is a compile-time error.
- **No pagination** — Wise returns all transactions in a single response. `HasMore` was removed in v0.4.0.
- **ListTransactions validates before calling the API** — empty currency or `From > To` returns an `errorfamily.Rejection` immediately without a network round-trip.
- **flake.nix must be git-tracked for buildflow** — The buildflow pre-commit hook runs `nix fmt .` which requires `flake.nix` to be in the git index. If you create or modify `flake.nix`, `git add` it before committing or the pre-commit hook fails.
- **GOEXPERIMENT=jsonv2 required** — go-branded-id v0.7.0 + go-error-family v0.11.0 import `encoding/json/v2`. Flake devShells, the go-standard check phase, and .golangci.yml build-tags are configured. BuildFlow detects the imports and sets the var for its tool subprocesses itself (the `.buildflow.yml` `env:` key was removed 2026-10-07 — restore it only if a step fails on the missing experiment). `go env -w` does NOT work (home-manager symlinks `~/.config/go/env` read-only). Plain shells are covered by the tracked `.envrc` (`use flake` + `use_go_env`; un-ignored via `!.envrc` because the buildflow-managed .gitignore block ignores `.envrc` by default) — do not "clean up" the negation.
- **Transaction.Date is UTC** — Wise statement dates (`"2006-01-02 15:04:05"`) carry no timezone. `parseWiseDate` interprets them as UTC via `time.Parse`. Callers comparing to local-time values must convert explicitly to avoid off-by-one-day errors at boundaries.

## Conventions

- **Webhook endpoints live on the quarterly versioned surface** — subscription CRUD uses `webhookSubscriptionsAPIVersion = "2026Q4"`, OTT uses `ottAPIVersion = "2026Q3"` (both `client.go`), NOT the legacy `/v1../v4` prefixes; the spec's server URL is authoritative and the two families roll over INDEPENDENTLY (shared constant split 2026-10-05). Webhook wire uses snake_case JSON (`trigger_on`, `created_at`, `sent_at`, `failure_reason_code`) unlike the camelCase core — tagliatelle is path-excluded for `internal/raw/webhooks.go` (a `//nolint` above `package` becomes a second package doc; a trailing nolint on the package clause does not suppress — use the exclusions rule). The envelope keeps undecoded payload bytes in a `jsontext.Value` (json/v2-native; `json.RawMessage` deliberately avoided) — surface via `event.RawData()`-style accessors, never re-marshal to read the payload. Subscription IDs are UUID strings (`WebhookSubscriptionID`, like `QuoteID`). Typed payloads come from the delivery envelope + live webhook-event reference (the plan's `deposits#*` events are undocumented, 2026-09-13 check). Rollover probe 2026-10-05: `2026Q4` subscriptions LIVE (401-gated, not 404; control `/9999Q1` → 404) but `one-time-token` is probe-blind (404 on every prefix incl. known-good `2026Q3`) — CRUD FLIPPED to `2026Q4`, OTT PARKED on `2026Q3` until live verification (probe procedure in TODO_LIST.md).
- **Error catalog is central** (`errors.go`, 2026-10-16) — every error code the SDK emits is a named constant there (single source of truth: call sites reference constants; tests pin wire values as literals — do NOT sed test files when renaming); the four response-shape sentinels (`ErrEmptyRateList`, `ErrAccountIdentificationCardinality`, `ErrOTTAlternativesShape`, `ErrTransferRefundAmountMissing`) are EXPORTED, declared with the `error` interface type (the sentinel-matching contract — type elision silently breaks it; `TestSentinelsStayInterfaceTyped` guards the declaration shape), always returned wrapped (`WrapCorruption`/`fmt.Errorf %w`), and consumer-matchable via `errors.Is` (pinned by `TestSentinelsMatchThroughProductionWraps`). New codes/sentinels go into the errors.go catalog AND the `TestErrorCodesUniqueAndWellFormed` list. `fetchByID` takes the named invalid-request code — never reassemble `"wise."+resource+…` at runtime (that hid `wise.user.invalid_request` from every literal grep). Contextual `fmt.Errorf("context: %w", err)` wraps at call sites stay anonymous BY DESIGN — the inner error carries the name.
- **Error-system matching contract** (`errors.go`, shipped v0.15.0) — `newAPIError` keeps Wise's structured envelope in `APIError.Details []WiseErrorDetail{Code WiseErrorCode, Message string}` (wire order; `Message` stays the flattened join byte-for-byte, pinned by fuzz). Two COMPLEMENTARY idioms, split pinned by `TestAsTypeAndIsAreComplementary`: **types via `errors.AsType`** (fields: status, RetryAfter, token); **curated codes via `errors.Is`** — `APIError.Is` compares `Details` codes against the `codeSentinels` map only (never message text or type identity) and is promoted through every embedding subtype, so it matches through any wrap chain; **any other code via `APIError.HasCode(WiseErrorCode)`** (open enum, 14 documented constants). Wave-1 = the 11 branching-story codes; `missing_value`/`invalid_file_extension`/`unexpected.error` deliberately have NO sentinel (DECISION 2026-10-16; `TestCodeSentinelsMapCuratedCodes` pins the map at exactly 11 — wave-2 needs a conscious pin update). Status drives the TYPE, body code drives the MATCH (5xx+`system_error` = retryable `*ServerError`; 400+it = `*BadRequestError`); end-to-end pin: `TestErrorSurfaceMappingMatrix`; reference: `docs/error-codes.md` + README decision tree. **`errors.AsType` does NOT descend into embedded fields** (subtypes have no `Unwrap`, scratch-proven 2026-10-17): `AsType[*APIError]` matches only bare-APIError statuses (402/409/422/…), never 400/401/403/404/429/5xx/SCA — the consumer idiom is extract-the-status-mapped-type (its promoted `HasCode`/`Details` behave identically); NEVER write migration/example text claiming `AsType[*APIError]` reaches subtypes (the v0.15.0 authoring caught exactly that fabrication). `gochecknoglobals` on `codeSentinels` suppressed with rationale (an errors.New-sentinel lookup table is the allowed-global shape).
- **Error handling** — Domain error types (`APIError`, `RateLimitError`, etc.) implement `go-error-family` interfaces (`ErrorCode`, `ErrorFamily`, `ErrorContext`, `IsRetryable`). Error wrapping at call sites uses `fmt.Errorf("context: %w", err)` — the inner error carries the classification. `errorfamily.WrapCorruption` is used specifically for response decode failures. `errorfamily.NewRejection` is used for "not found" and client-side validation errors.
- **Error-context convention** — every error type exposes `ErrorContext()`. `APIError` pins `status_code` + first granular code as `wise_code`; `RateLimitError` adds `retry_after`/`rate_limited_by`; `SCAChallengeError` adds `approval_result`/`approval_token_issued` (bools, never the raw OTT). The other four types deliberately have NO override (promoted `APIError` context; `TestErrorContexts` pins it — an override with nothing new is surface without information). ONLY `RateLimitError`/`ServerError` implement `IsRetryable` (absence on the other five is pinned by `TestIsRetryableContract`). Mapper/validation messages carry the raw wire input; unreadable bodies surface as `"(response body could not be read: …)"`, never silently empty.
- **Validation idiom is exactly two forms, deliberately** — `requireID` for branded IDs (zero/empty → Rejection), inline checks for everything else (currency, dates, enums, request fields). A generic `requireNonEmpty` helper was considered and DECLINED (2026-09-13): non-ID validations differ in predicate (empty vs unset vs malformed), in wire field name, and in message shape, so the helper would take 3+ parameters to say what the inline check already says — the "two-idiom drift" is actually the correct split. Do not introduce a third form.
- **Error types** — `newAPIError()` in `errors.go` handles all status-code-to-type mapping. Never construct `AuthError`/`NotFoundError` etc. directly outside that function.
- **Error families** — `APIError`/`AuthError`/`NotFoundError` → Rejection (not retryable). `RateLimitError`/`ServerError` → Transient (retryable).
- **`requireID` for every branded-ID guard** — Zero/empty branded-ID validations go through `requireID` (in `ids.go`): `if err := requireID(profileID, "wise.<domain>.invalid_request", "profileID"); err != nil { return nil, err }`. It checks `ID.IsZero()`, so it covers int64 IDs and string `QuoteID` alike. Never hand-roll `x.Get() == 0 { errorfamily.NewRejection(...) }` blocks; non-ID field validations (currency, dates, enums) stay inline.
- **`toTransfer` wraps raw transfer mapping** — GetTransfer/CreateTransfer/CancelTransfer map responses via `toTransfer(label, transfer)` (`transfers.go`). The label is the full error-message prefix ("map transfer", "map created transfer", "map cancelled transfer"); the resulting messages are pinned by tests.
- **Details wire keys have one spelling** — `CreateTransferRequest.detailsWire()` delegates to `TransferRequirementsDetails.toWire()`. New details fields belong on `TransferRequirementsDetails` first; mirror them onto `CreateTransferRequest` only if the create endpoint accepts them.
- **Every error type has its own `ErrorCode()`** — `wise.api_error`, `wise.rate_limit`, `wise.auth`, `wise.not_found`, `wise.server`.
- **`Money` is a value object, NOT a math library** — `Money{Cents, Currency}` exists to pair cents with currency at the serialization boundary so mismatched amounts are unrepresentable. It deliberately has no `Add`/`Sub`/`IsZero`/`IsNegative`/`Equal` methods. The SDK is an anti-corruption layer: call the API, parse responses, return typed data. Financial arithmetic is the consumer's domain logic, not the SDK's job.
- **`DetailType` typed enum** — `ListTransactionsRequest.Type` is `DetailType` (not `string`) as of v0.5.0. The `DetailType*` constants (`DetailTypeCardPayment`, etc.) are typed values. Use `req.Type = wise.DetailTypeCardPayment` instead of `req.Type = "CARD_PAYMENT"`.
- **`setHeaders` (renamed from `setAuth`)** — sets `Authorization`, `X-External-Correlation-Id` (client-wide + ctx override via `WithRequestCorrelationID`; ctx wins), and the SCA approval token. Add new headers here, not per-endpoint. Endpoint-specific negotiation headers (e.g. `Accept-Minor-Version: 1`) go through the `extraHeaders` hook; raw responses through `getRaw`.
- **Retry exhaustion preserves typed errors** — the executor is go-retry (ADR 003): on exhaustion the `ErrExhausted` chain carries the final attempt's typed error via `WithCause`, so `errors.AsType` reaches `*RateLimitError`/`*ServerError` with no unwrap bridge. `executeWithLogging` classifies each attempt's non-2xx via `checkError`; that typed error drives `isRetryableError` and the `DelayFunc` Retry-After honoring (capped at `WithRetry`'s max delay; go-retry counts TOTAL attempts — `MaxAttempts = maxRetries + 1`). Locked by the 429 BDD tests; do not regress. `RequestLog.RetryAfterDelay` (options.go): the `DelayFunc` emits one extra delay-decision entry through the SAME `LogRequest` channel (`Status: 429`, honored wait in `RetryAfterDelay`, `Method`/`URL` empty), pinned by the Ginkgo Context asserting the 3-entry sequence (429 → delay entry → 200).
- **Go 1.26 `x509.MarshalPKIXPublicKey` returns `([]byte, error)`** — the two-value signature tripped the build once; same for test helpers.
- **Spec-conformance gate** — `spec_conformance_test.go` records every mock-harness exchange and validates it against the vendored OpenAPI 3.1 snapshot (`docs/reviews/wise-api-openapi.json`, kin-openapi legacy router); version-prefix stripping maps SDK wire paths onto unversioned templates. Exemptions: statement file formats (spec declares only `.json`), legacy bare-array `/v2/accounts`, per-exchange `exemptResponseSchema` for corrupt fixtures. `conformanceOptions()` goes to BOTH request and response validation. `date-time` is deliberately permissive (live shapes are looser than RFC3339). The coverage guard is SHUFFLE-PROOF: `TestMain` asserts floors only after the suite completes (gated by `conformanceSuiteCompleted` — a mid-suite guard once vacuously passed); a `-run` filter excluding the suite exits 0 by design. Floors: ≥25 templates / ≥60 exchanges / ≥4 statement variants (actuals: 25/180/6); spec-sanity pins OpenAPI 3.1.0 + ≥150 paths. Statement `type` is `StatementType` (COMPACT|FLAT), NOT DetailType. `CreateBalance` must send `X-idempotence-uuid` (auto v4 unless `CreateBalanceRequest.IdempotencyKey`). Funding errors are `text/plain`, not the JSON envelope. Go named-return parameters SHADOW package variables of the same name (the coverage counters hit this; avoid same-named returns).
