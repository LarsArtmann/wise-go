# wise-go — AGENTS.md

## Gotchas

- **Outgoing query timestamps must be UTC `Z`** — Wise rejects zone-offset timestamps (`+02:00`) with HTTP 422 `wrong.date.format`. All outgoing query timestamps go through `formatWiseTimestamp` (`helpers.go`). Live regression 2026-08-19..21: every bank-sync transfers call failed for ~2.5 days because `time.Now()` carried CEST (fixed in v0.8.1). Never format `time.Time` directly into query params.
- **SCA 403s have an empty body** — Wise answers SCA-protected endpoints (balance statements for UK/EEA profiles among them) with HTTP 403 and NO body; the verdict and one-time token live in the `x-2fa-approval-result` / `x-2fa-approval` response headers. The client classifies this as `*SCAChallengeError` (not `*AuthError`); `TwoFAApprovalToken()` extracts the OTT, `WithSCAApprovalToken` completes the challenge flow, and the OTT endpoints (`ott.go`, `/2026Q3/one-time-token/...` via `ottAPIVersion`) clear challenges programmatically. **The OTT value must never appear in an error string or log** — callers fetch it via `TwoFAApprovalToken()`; `SCAChallengeError.Error()` deliberately reports only `token issued: true/false`. Challenge-type values are UPPERCASE (SMS/WHATSAPP/VOICE) while the per-channel endpoint paths are lowercase — `OTTChannel.challengeType()` is the single mapping; never compare them directly.
- **Inconsistent timestamp formats** — Wise emits timestamps inconsistently: full RFC3339 (`2020-05-27T10:27:22Z`), zoneless `T`-separated (live `/v2/profiles` `createdAt`), space-separated statement dates (`2020-05-27 10:27:22`), milliseconds-with-numeric-zone delivery estimates (`2018-01-10T12:15:00.000+0000`), and no-millis numeric-zone rate timestamps (`2026-10-07T00:17:01+0000`, live `/v1/rates` `time` field — live regression 2026-10-07, killed bank-sync FX totals). One tolerant parser (`parseWiseTimestamp`) handles all of them; zoneless values are UTC. Never parse Wise timestamps with a single strict layout.
- **Amount vs Total** — `Transaction.Amount.Cents` is absolute value (always positive). `Transaction.Total.Cents` preserves sign (negative for debits). Getting this wrong silently produces wrong data. Both are `Money` fields (cents + currency paired).
- **CARD_PAYMENT vs CARD_REFUND classification** — `CARD_PAYMENT` always maps to `TransactionTypeCard` regardless of amount sign. Only `CARD_REFUND` is amount-dependent (positive → `TransactionTypeRefund`, non-positive → `TransactionTypeCard`). Do not re-group these into one case branch — the README contract requires separate handling.
- **Balance filtering** — `ListBalances` silently drops `Visible: false` and `InvestmentState != "NOT_INVESTED"` balances. `GetBalance` uses the direct per-balance endpoint (GET /v4/profiles/{id}/balances/{id}) and does NOT filter — hidden/invested balances are retrievable individually. The live v4 endpoint requires `?types=STANDARD,SAVINGS` (sent automatically via `balanceTypesQuery` in `balances.go`); a bare path returns `400 query.types: NotNull`. The public `BalanceType` enum is lowercase ("standard"/"savings") but the wire uses UPPERCASE — convert via `balanceTypeWire`/`parseBalanceType`.
- **Sandbox URL migrated to V2** — As of Nov 2025, Wise migrated sandbox from V1 (`api.sandbox.transferwise.tech`) to V2 (`api.wise-sandbox.com`). V1 was fully deprecated June 30, 2026. The SDK's `SandboxURL` constant was updated accordingly. Data created in V1 after April 1, 2025 was NOT migrated.
- **Global headers (Apr 2026)** — Wise documents `X-External-Correlation-Id` (distributed tracing) and `x-trace-id` on all operations. The SDK supports `X-External-Correlation-Id` via `WithCorrelationID`. The `x-trace-id` header is typically set by intermediaries, not clients.
- **Retry-After + X-Rate-Limited-By headers (Apr 2026)** — 429 responses include `X-Rate-Limited-By` identifying the rate-limit scope (e.g., "ip", "profile") and `Retry-After`. `RateLimitError.RetryAfter` is parsed from the HTTP `Retry-After` header (delta-seconds or HTTP-date), falling back to 1 second; `RateLimitError.RateLimitedBy` captures the scope.
- **`//nolint:bodyclose`** — `getWithQuery` intentionally defers body close via `responseCloser`: the response outlives the helper, so the caller closes it. Don't remove it.
- **Two-layer type design** — Raw API structs (`raw.Profile`, `raw.Balance`, `raw.StatementTransaction`, `raw.Transfer`, `raw.Quote`, `raw.Recipient`, `raw.ExchangeRate` in `internal/raw/types.go`) intentionally use primitives (`int64`/`string`/`float64`) to match Wise's JSON wire format. The parsed result types (`Profile`, `Balance`, `Transaction`, `Transfer`, `Quote`, `Recipient`, `ExchangeRate` in `types.go`) convert these into strong types (branded IDs, enums, `time.Time`, `Money`). Raw types are in `internal/raw` and invisible to consumers. The raw/public `TransferRequirement` mirror pair (suppressed via `// art-dupl:accept` directives at both sites, verified 2026-09-13) is the accepted price of tag-free public types — do NOT merge via type aliases (aliases would leak Wise's wire JSON tags into the public serialization surface).
- **art-dupl suppression is in-source directives** — `// art-dupl:accept <rationale>` comments ARE the suppression config (no baseline file, declined 2026-09-13). As of 2026-09-27 (second pass) a `-t 2 --type-aware` run reports 0 actionable; remaining accepted clones: the requireID-guards+path idiom trio (GetBalance/GetQuote/FundTransfer), the ownedByCustomer wire-field tails, and two exhaustive-switch bool predicates. **Placement gotcha: body-interior clones are only suppressed when the directive sits INSIDE the cloned line range** (directly above the duplicated lines); a directive on the enclosing function's doc comment suppresses nothing — doc-comment placement only works for declaration-level clones like the struct mirror pair. The trio's directives live IN-BODY for exactly this reason (an earlier pass put them on doc comments and the trio resurfaced actionable). The account-requirements GET/refresh pair shares `quoteAccountRequirements` (quotes.go), and webhook payload decoders share `decodeWebhookEvent[T]` + `raw.OccurredAtCarrier`/`raw.WebhookOccurredAt` — extend those instead of re-duplicating. **Enforced-gate decision (2026-10-07)**: the accepted baseline stays POLICY, not an enforced gate — no buildflow step or CI job runs art-dupl; revisit at CI re-enable as a warn-first (non-blocking) job. Rationale: CI disabled, buildflow has no custom-step hook for it, and suppression is in-source, so later enforcement needs no config migration. Until then run `/home/lars/go/bin/art-dupl -t 2 --type-aware .` manually when touching cloned-adjacent code (0 actionable, exit 0 as of 2026-10-07, 16 clone groups).
- **Quote IDs are UUID strings** — Unlike profile/balance/transfer/recipient IDs, which are `int64`, Wise quote IDs are UUIDs (`string`). `QuoteID` is therefore `id.ID[QuoteBrand, string]` and constructed with `NewQuoteID("...")`.
- **Recipient `details` is polymorphic** — The required fields depend on currency and route (e.g. `sortCode`+`accountNumber` for GBP, `iban` for many EUR corridors). The SDK exposes `Recipient.Details` and `CreateRecipientRequest.Details` as `map[string]string`; callers must use the account-requirements endpoints to discover the exact fields for their corridor.
- **Transfer creation requires `customerTransactionId`** — This UUID is mandatory for idempotency. Reusing the same `customerTransactionId` with the same `quoteUuid` and `targetAccount` returns the existing transfer instead of creating a duplicate.
- **Branded IDs are the public API** — Every client method taking an ID uses branded types (`ListBalances(ctx, ProfileID)`, `GetBalance(ctx, ProfileID, BalanceID)`, `ListTransactionsRequest{ProfileID, BalanceID}`). Construct with `NewProfileID`/`NewBalanceID`/`NewTransactionID`; unwrap with `.Get()`. Mixing entity IDs is a compile-time error.
- **No pagination** — Wise returns all transactions in a single response. `HasMore` was removed in v0.4.0.
- **ListTransactions validates before calling the API** — empty currency or `From > To` returns an `errorfamily.Rejection` immediately without a network round-trip.
- **flake.nix must be git-tracked for buildflow** — The buildflow pre-commit hook runs `nix fmt .` which requires `flake.nix` to be in the git index. If you create or modify `flake.nix`, `git add` it before committing or the pre-commit hook fails.
- **GOEXPERIMENT=jsonv2 required** — As of go-branded-id v0.5.1 and go-error-family v0.10.0, both deps import `encoding/json/v2` which requires `GOEXPERIMENT=jsonv2` to build. The flake devShells, the go-standard check phase, and .golangci.yml build-tags are all configured for this. For buildflow: `.buildflow.yml` has an `env:` key that injects `GOEXPERIMENT: jsonv2` into all tool subprocesses (go-fix, test-race, govalid-generate, golangci-lint). `go env -w GOEXPERIMENT=jsonv2` does NOT work here — Nix home-manager symlinks `~/.config/go/env` into the read-only store.
- **Transaction.Date is UTC** — Wise statement dates (`"2006-01-02 15:04:05"`) carry no timezone. `parseWiseDate` interprets them as UTC via `time.Parse`. Callers comparing to local-time values must convert explicitly to avoid off-by-one-day errors at boundaries.
- **go-structure-linter "errors" are known false positives** — buildflow's
  go-structure-linter reports ~20 error-severity findings that are deliberate
  non-fixes for this repo: `root-package-files` (the SDK is a root-package
  library by design, not /internal or /pkg) and `go-version` (the repo pins
  go 1.26 while newer toolchains exist). Do NOT restructure or bulk-bump to
  satisfy them. Real golangci findings in touched code are fixed on sight.

- **buildflow auto-configure is dangerous** — `buildflow --fix` can add 40+ linters (including irrelevant ones like `arangolint`, `clickhouselint`, `depguard`) that produce false positives. If buildflow modifies `.golangci.yml`, review the diff carefully. The project's curated linter list is intentional; do not let buildflow replace it with a generic "enable everything" config.
- **Money + Currency value objects** — All monetary amounts are `Money{Cents int64, Currency Currency}`. `Currency` is a typed string with `NewCurrency(s)` validation (3-letter uppercase ASCII). `ListTransactionsRequest.Currency` is `Currency` (not `string`). Use `wise.Currency("EUR")` for direct construction or `NewCurrency("EUR")` for validated. The `toMoney` helper in `helpers.go` converts `raw.BalanceAmount` to `Money` with currency validation.
- **flake.nix fileset must list all Go files** — The `buildGoModule` check uses an explicit `lib.fileset.unions` list. When adding a new `.go` file (e.g. `internal/raw/types.go`), add it to the fileset in `flake.nix` or the Nix build will fail with "undefined" errors.
- **Changelog-only commits structurally fail pre-commit** — dprint's config excludes `**/CHANGELOG.md`, so staging only the changelog leaves dprint with zero files → exit 14 → BuildFlow blocks the commit. Fold changelog edits into a commit that also touches at least one dprint-covered file (code, docs, yaml).
- **Flake links-check fileset must contain every README link target** — Separate from the Go fileset: `nix flake check` runs a links check over README that requires each relative link target to be inside the `links` fileset union in `flake.nix`. Adding a new relative link (e.g. to `.github/workflows/`) without adding the target to that union fails the check with "File not found". Run `nix flake check` after any README link change.
- **Auto-git daemon races edits and commits** — A commit daemon runs continuously: it can commit mid-edit (aborting your commit with "cannot lock ref HEAD"), author commits with its own messages, and sweep temp files (e.g. `buildflow-fsprobe-*`) into history. Always check `git status`/`git log` before and after committing, and verify a daemon-authored commit actually contains what you wrote (its message may not match your intent).
- **`newAPIError` takes a `string` body and returns `error`** — In tests, construct `&APIError{...}`/`&RateLimitError{...}` directly instead of calling `newAPIError` and unwrapping; the signature (`status int, body string, ...`) does not fit table-driven fixtures.

- **`Accept-Minor-Version: 1` on account-requirements** — Wise versions the account-requirements response schema; minor version 1 includes the recipient name/email fields and is what Wise recommends for all new integrations. The SDK always sends it on those endpoints via the `extraHeaders` hook (see `quotes.go`), never via `setHeaders` (it is endpoint-specific content negotiation, not auth). Any future account-requirements endpoint must send the same header.

- **Coverage badge job** — `.github/workflows/ci.yml` has a `coverage-badge` job that runs after every push to master WHEN CI IS ENABLED: it measures coverage, rewrites the percentage in README.md, and pushes back. It owns its own concurrency group with `cancel-in-progress: false` (queue, never abort mid-push) and rebases before pushing. Consequence: the badge percentage in the repo lags local measurement until the branch is pushed — and it is currently FROZEN because the CI workflow is disabled on GitHub (see Build & Dev); the badge shows the last CI-measured value, not current coverage (locally measured 93.1% against the 90.0 floor, 2026-10-07).
- **Godoc examples are compile-only** — every `Example*` func in `example_test.go` carries `//nolint:testableexamples` because the examples deliberately have no `// Output:` comment: they construct real clients and would hit the live API if executed. They exist for godoc, not for `go test`; do not add Output comments or remove the nolints.

- **`GetTransferReceipt` 404 means "no receipt yet"** — Wise answers the receipt endpoint with 404 until the transfer reaches `outgoing_payment_sent`; the SDK surfaces `*NotFoundError`, which consumers must treat as "not paid out (yet)", not a hard failure. Not SCA-protected (unlike statements).
- **Historical reports: annotate inline, then archive** — point-in-time docs under `docs/status|planning|reviews/` get inline `~~item~~ done at <hash>` resolutions (docs-health ANNOTATE); a file whose every item shipped/superseded/routed is `git mv`-archived into the sibling `archived/` dir. The generated HTML/D2 scan artifacts (2026-07-18 era) are LEAVE-ALONE: re-running the producing skill supersedes them; annotating HTML adds no value.

- **branching-flow panic: two suppressed false positives in webhooks.go** — `ListProfileWebhookSubscriptions` dereferences `*mapped` and `decodeWebhookEvent` dereferences `*payload`; both helpers provably never return `(nil, nil)` (the only non-error return is `&struct{...}, nil`), but the analyzer has no interprocedural/generics tracking. Do not add nil checks.

## Conventions

- **Webhook endpoints live on the quarterly versioned surface** — the subscription CRUD uses `webhookSubscriptionsAPIVersion = "2026Q4"` and the OTT endpoints use `ottAPIVersion = "2026Q3"` (both in `client.go`), NOT the legacy `/v1../v4` prefixes the rest of the SDK uses; the OpenAPI spec's server URL is authoritative and the two families roll over INDEPENDENTLY (a shared constant was split 2026-10-05 when only the webhook surface verified live). The webhook wire also uses snake_case JSON keys (`trigger_on`, `created_at`, `sent_at`, `failure_reason_code`) unlike the camelCase core API — tagliatelle is path-excluded for `internal/raw/webhooks.go` (a `//nolint` above `package` becomes a second package doc, and a trailing nolint on the package clause does not suppress — use the exclusions rule). The envelope keeps undecoded payload bytes in a `jsontext.Value` (json/v2-native raw type; `json.RawMessage` deliberately avoided) — surface with `event.RawData()`-style accessors, never re-marshal the envelope to read the payload. Webhook subscription IDs are UUID strings (`WebhookSubscriptionID = id.ID[WebhookSubscriptionBrand, string]`, like `QuoteID`). Wise's webhook delivery envelope and the live webhook-event reference are the source for typed payloads — the plan's `deposits#*` events turned out to be undocumented (2026-09-13 live check). Rollover probe (2026-10-05): `2026Q4` webhook subscriptions is LIVE (401 auth-gated, not 404; control `/9999Q1/...` → 404) but `one-time-token` is probe-blind — 404 on every prefix INCLUDING known-good `2026Q3` — so the subscription CRUD FLIPPED to `2026Q4` while OTT stays PARKED on `2026Q3` until it verifies live (probe procedure in TODO_LIST.md).
- **Error handling** — Domain error types (`APIError`, `RateLimitError`, etc.) implement `go-error-family` interfaces (`ErrorCode`, `ErrorFamily`, `ErrorContext`, `IsRetryable`). Error wrapping at call sites uses `fmt.Errorf("context: %w", err)` — the inner error carries the classification. `errorfamily.WrapCorruption` is used specifically for response decode failures. `errorfamily.NewRejection` is used for "not found" and client-side validation errors.
- **Error-context convention** — Every error type exposes `ErrorContext()`. `APIError` pins `status_code`; `RateLimitError` adds `retry_after`/`rate_limited_by`; `SCAChallengeError` adds `approval_result`/`approval_token_issued` (bool, never the raw OTT). `AuthError`/`NotFoundError`/`ServerError` intentionally have NO override — they expose the promoted `APIError` context, and `TestErrorContexts` pins that promotion (an override with nothing new to add is API surface without information). Retryability: ONLY `RateLimitError` and `ServerError` implement `IsRetryable`; the other four rely on interface absence (pinned by `TestIsRetryableContract`). Mapper/validation error messages carry the raw wire input (`fmt.Errorf("total amount %v %q: %w", value, currency, err)`) so a corrupt response is diagnosable from logs alone; unreadable response bodies are surfaced as `"(response body could not be read: …)"` in `checkError`, never as a silently empty body.
- **Validation idiom is exactly two forms, deliberately** — `requireID` for branded IDs (zero/empty → Rejection), inline checks for everything else (currency, dates, enums, request fields). A generic `requireNonEmpty` helper was considered and DECLINED (2026-09-13): non-ID validations differ in predicate (empty vs unset vs malformed), in wire field name, and in message shape, so the helper would take 3+ parameters to say what the inline check already says — the "two-idiom drift" is actually the correct split. Do not introduce a third form.
- **Error types** — `newAPIError()` in `errors.go` handles all status-code-to-type mapping. Never construct `AuthError`/`NotFoundError` etc. directly outside that function.
- **Error families** — `APIError`/`AuthError`/`NotFoundError` → Rejection (not retryable). `RateLimitError`/`ServerError` → Transient (retryable).
- **`requireID` for every branded-ID guard** — Zero/empty branded-ID validations go through `requireID` (in `ids.go`): `if err := requireID(profileID, "wise.<domain>.invalid_request", "profileID"); err != nil { return nil, err }`. It checks `ID.IsZero()`, so it covers int64 IDs and string `QuoteID` alike. Never hand-roll `x.Get() == 0 { errorfamily.NewRejection(...) }` blocks; non-ID field validations (currency, dates, enums) stay inline.
- **`toTransfer` wraps raw transfer mapping** — GetTransfer/CreateTransfer/CancelTransfer map responses via `toTransfer(label, transfer)` (`transfers.go`). The label is the full error-message prefix ("map transfer", "map created transfer", "map cancelled transfer"); the resulting messages are pinned by tests.
- **Details wire keys have one spelling** — `CreateTransferRequest.detailsWire()` delegates to `TransferRequirementsDetails.toWire()`. New details fields belong on `TransferRequirementsDetails` first; mirror them onto `CreateTransferRequest` only if the create endpoint accepts them.
- **Every error type has its own `ErrorCode()`** — `wise.api_error`, `wise.rate_limit`, `wise.auth`, `wise.not_found`, `wise.server`.
- **`Money` is a value object, NOT a math library** — `Money{Cents, Currency}` exists to pair cents with currency at the serialization boundary so mismatched amounts are unrepresentable. It deliberately has no `Add`/`Sub`/`IsZero`/`IsNegative`/`Equal` methods. The SDK is an anti-corruption layer: call the API, parse responses, return typed data. Financial arithmetic is the consumer's domain logic, not the SDK's job.
- **`DetailType` typed enum** — `ListTransactionsRequest.Type` is `DetailType` (not `string`) as of v0.5.0. The `DetailType*` constants (`DetailTypeCardPayment`, etc.) are typed values. Use `req.Type = wise.DetailTypeCardPayment` instead of `req.Type = "CARD_PAYMENT"`.
- **`setHeaders` (renamed from `setAuth`)** — Sets `Authorization`, `X-External-Correlation-Id` (client-wide + per-request override from the context via `WithRequestCorrelationID`; ctx wins), and the SCA approval token. When adding new headers, extend `setHeaders` in `client.go`, not the individual endpoint methods. Endpoint-specific negotiation headers (e.g. `Accept-Minor-Version: 1` on account-requirements) go through the `extraHeaders` hook in `request`/`getWithQueryHeaders`; raw (non-JSON) responses go through `getRaw`.
- **Retry exhaustion preserves typed errors** — the retry executor is go-retry (ADR 003, executed 2026-09-16): on exhaustion the `ErrExhausted` chain carries the final attempt's typed error via `WithCause`, so `errors.AsType` reaches `*RateLimitError`/`*ServerError` with no unwrap bridge. `executeWithLogging` classifies each attempt's non-2xx via `checkError` — that typed error is what drives `isRetryableError` and the `DelayFunc` Retry-After honoring (capped at `WithRetry`'s max delay; go-retry counts TOTAL attempts, so `MaxAttempts = maxRetries + 1`). Locked in by the 429 BDD tests; do not regress. `RequestLog.RetryAfterDelay` (options.go, 2026-10-07) — the `DelayFunc` in `New()` emits one extra delay-decision entry through the SAME `LogRequest` channel: `Status: 429`, the honored wait as a `time.Duration` in `RetryAfterDelay`, `Method`/`URL` empty; pinned by the "on a Retry-After-honored delay" Ginkgo Context asserting the 3-entry sequence (429 exchange → delay entry → 200 exchange).
- **Go 1.26 `x509.MarshalPKIXPublicKey` returns `([]byte, error)`** — the two-value signature tripped the build once; same for test helpers.
