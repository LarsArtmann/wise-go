Library-Specific Adjustments to the Standard Template

The skill's Go template assumes a binary (packages.default = buildGoModule {...}). wise-go is a library, so:

  • No packages.default. Consumers do not nix run or install wise-go via Nix; they go get github.com/larsartmann/wise-go. The buildGoModule derivation would build nothing useful.
  • checks.test uses stdenvNoCC.mkDerivation instead of buildGoModule. It runs go test -race -coverprofile=coverage.out in a hermetic sandbox and installs the coverage report to $out.
  • checks.lint mirrors the structure. Runs golangci-lint run --timeout=5m against the same source fileset.
  • Source fileset is explicit via lib.fileset.unions [...] — only .go files, go.mod/go.sum, and the lint config enter the sandbox. No docs/, no .github/, no review artifacts.
  • GOWORK=off + GOPRIVATE=github.com/larsartmann pinned in both devShells, matching the existing convention.
  • go_1_26 pinned via the goPkg let-binding, matching go.mod's go 1.26.4.

Optional Follow-Ups

Add nix flake check to GitHub Actions

Optional but recommended: add a nix: job to .github/workflows/ci.yml using cachix/install-nix-action + nix flake check. This catches non-reproducible builds in CI, not just locally. Cachix caching recommended for the Go module fetch step.

Add .envrc for direnv integration

Once the devShell is trusted, a one-line .envrc (use flake) makes the devShell load automatically on cd. Already covered by the .direnv/ entry in .gitignore.
