# wise-go v0.13.0

> Published 2026-10-07 via `gh release create v0.13.0 --latest` (cut from the
> CHANGELOG `[0.13.0]` section, 2026-10-07).

An observability and release-hygiene release. The retry loop now narrates a
`Retry-After`-driven delay, and a new dependency pin-sync gate turns flake-pin
drift into a red check — after it caught a live split-brain in this very repo.
41 client methods (unchanged); one additive public field.

## Highlights

- **`RequestLog.RetryAfterDelay`** — when Wise answers a 429 with a
  `Retry-After` hint and the retry loop honors it, the client emits one extra
  `LogRequest` entry describing the decision: `Status` 429, the honored wait in
  `Duration` and `RetryAfterDelay`, and empty `Method`/`URL` because no
  exchange happened. Purely additive; a request with no usable hint (including
  `Retry-After: 0`) emits no delay entry.
- **`pin-sync` dependency gate** — `checks.pin-sync` runs hermetically inside
  `nix flake check` and asserts that every in-house dependency is pinned in
  `flake.nix` to the exact commit of the version `go.mod` requires;
  `nix run .#pin-sync` additionally resolves each version tag on GitHub to
  catch a pin left stale after a `go get` bump.
- **Dependency flake pins realigned** — the `go-branded-id`,
  `go-error-family`, and `go-retry` inputs were pointing at annotated
  tag-object IDs rather than commits, and the first two had slipped two and
  one minor versions behind `go.mod`. They now pin the exact commit of
  v0.7.0, v0.11.0, and v0.7.1 — the same versions `go test` already built
  against.

## Changed

- Repository quality gates (no API change beyond the field above): a
  one-command `nix run .#pre-release` release gate (dirty-tree check, build,
  vet, race tests, lint, `nix flake check`, `doc-verify`,
  `release-notes-check`, `pin-sync`, `apidiff`, with an optional `--shuffle`
  loop); `nix run .#release-notes-check` for code spans split across lines and
  repo-relative links in `docs/releases/*.md`; a `checks.md-go-snippets` flake
  check that parse-checks every fenced Go block in the README and `docs/**`;
  and a `meta.description` on each flake app.
- `doc-verify` now also gates the latest release-notes client-method count; the
  OpenAPI spec-conformance coverage guard asserts its floors in `TestMain` after
  the suite completes, making it shuffle-proof; test coverage rose to 93.1%
  (floor 90.0).

## Fixed

- Retry-After delay-entry coverage: a regression now pins that two consecutive
  429s carrying a `Retry-After` hint emit exactly two delay-decision entries
  (the `Retry-After: 0` no-entry case was already pinned).
- CONTRIBUTING documents `--shuffle` on tag day and the flake-pin invariant: a
  `go.mod` version bump must update the matching input `rev` in the same
  change, because a pinned `rev` is immutable under `nix flake update`.

## Compatibility

Additive only. The new `RequestLog` field does not affect existing consumers,
and the dependency realignment changes no exported API. No migration required.
