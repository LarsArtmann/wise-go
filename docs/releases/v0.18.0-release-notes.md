# wise-go v0.18.0

The visibility release: the SDK reads Wise's profile activity feed, and the
recipient list works against the live wire. 48 client methods across 16
resource files (47 and 15 at v0.17.0).

## Highlights

- **`ListActivities`** pages through a profile's activity feed
  (`GET /v1/profiles/{id}/activities`): transfers, card payments, deposits
  and conversions, newest first, with typed open enums for type, status and
  resource. The endpoint is not SCA-protected: a personal API token reads it
  on profiles whose statements answer 403.
- **Activity amounts are display text.** `ActivityAmount` parses one plain
  amount into `Money` (`Present` true) and always keeps Wise's raw `Text`;
  `Credit` marks money in. A currency pair or another locale stays unparsed
  rather than being misread by a factor of a thousand.
- **The feed is not the ledger.** It is profile-scoped, does not itemize
  fees, and a two-legged row names no balance. Read statements for the book
  of record.
- **Recipient list fixed against the live wire.** `GET /v2/accounts` answers
  a page envelope and the holder name arrives as `name.fullName`; the SDK
  had decoded a bare array and filtered with a parameter the wire ignores.
  Verified live 2026-11-26: 53 recipients across five profiles, 30 on one
  profile through two seek pages.
- **`Money.Amount()`** bridges to the fleet-canonical money type.

## Compatibility

No breaking changes to signatures. Two behavior changes in
`ListRecipients`:

- It now returns results (the previous bare-array decode failed on every
  call).
- An empty result is an empty slice, not nil.

## Verification

- Unit and BDD suites, lint, and the spec-conformance gate against the
  vendored OpenAPI snapshot, with the recipient list exchanges now validated.
- A read-only live probe on 2026-11-26 compared per-profile recipient counts
  against an independent dump of the same endpoint.
