# wise-go v0.14.0

> Published 2026-10-16 via `gh release create v0.14.0 --latest` (cut from the
> CHANGELOG `[0.14.0]` section, 2026-10-16).

A surface-expansion and typing release: the transfer category gains its
payment-side read, its paperwork downloads, and the originator (third-party)
family; the transfer webhook events become typed payloads; and two breaking
migrations land — the SCA one-time token is now a distinct type, and
`GetBankAccountDetails` moves to Wise's 2027Q1 account-details surface.
46 client methods across 17 resources as of 2026-10-16 (41 at the v0.13.0
tag; +5 endpoints shipped on master since).

## Highlights

- **Originator (third-party) transfers** — `CreateThirdPartyTransfer` and
  `GetThirdPartyTransfer` cover Wise's `third-party-transfers` family: money
  moved on behalf of a named third party, funded through your own quote. The
  originator compliance block is a typed PRIVATE/BUSINESS oneOf
  (`Originator`, `OriginatorLegalEntityType`, `OriginatorName`,
  `OriginatorAddress`); `OriginalTransferID` is the idempotency key and the
  reference Wise keys compliance on.
- **Typed transfer webhook payloads** — `transfers#active-cases` decodes into
  `TransferActiveCases` (case list normalized to nil when absent) and
  `transfers#refund` into `TransferRefund` (refund amount as `Money`; a
  missing amount surfaces as corruption instead of a silent zero), joining
  the existing typed payload set behind `ParseWebhookEvent`.
- **`OneTimeToken`** — the SCA one-time token (OTT) is a distinct type now:
  `NewOneTimeToken` validates, `IsZero()` reports absence, and every
  OTT-taking surface (`GetOTTStatus`, `TriggerOTT`, `VerifyOTT`,
  `ClearSCAChallenge`, `WithSCAApprovalToken`,
  `SCAChallengeError.TwoFAApprovalToken`) is typed. An OTT can no longer be
  passed where an OTP code or an API key is expected. The tokenless-SCA
  contract (403 with verdict header but no OTT) is pinned by a test.
- **2027Q1 account-details migration** — Wise removed the profile-keyed
  `GET /v1/profiles/{id}/account-details` and relocated the read to
  `GET /balances/account-details/{id}`. `GetBankAccountDetails` now takes the
  new `AccountDetailsID` brand and returns a typed oneOf identification
  (BE IBAN / GB sort-code pair / US routing pair) with the
  exactly-one-member invariant enforced as a corruption error. The vendored
  OpenAPI snapshot was re-vendored (173 to 188 paths) and the spec-drift gate
  added along the way.
- **Transfer paperwork and funding reads** — `ListTransferPayments` (the
  completed funding payments of a transfer), `GetUSCombinedReceipt` (US
  combined confirmation PDF), and `GetTransferNOC` (the Indian FIRC
  no-objection certificate) complete the transfer category's read side.
- **Godoc examples** — the example set grew to 32 `Example*` funcs, now
  covering every resource group including the new transfer reads and the
  originator flow (compile-only per repo convention).

## Compatibility

Two breaking changes, both with mechanical migrations:

1. **OTT typing** — wrap OTT strings in `wise.OneTimeToken(...)` (or
   validate with `wise.NewOneTimeToken`) at the five typed surfaces. The
   common flow is unaffected: constructing from
   `SCAChallengeError.TwoFAApprovalToken()` and passing straight to the OTT
   endpoints or `WithSCAApprovalToken` compiles unchanged. `OTTStatus.ActionType`
   is the open enum `OTTAction`; comparisons against literals still compile
   via untyped constants.
2. **Account details** — swap the profile ID + balance ID pair for
   `NewAccountDetailsID(...)`; the old wire shape (bank/receive-option
   fields) is replaced by the typed identification oneOf. The previous
   endpoint 404s live since the 2027Q1 roll, so the migration is mandatory,
   not optional.

Everything else is additive: new endpoints, new typed payloads, new
constants, and documentation (SCA endpoint matrix, transfer status
lifecycle, dependency-injection recipe). No behavioral change to existing
surfaces.
