# wise-go v0.15.0

> Published 2026-10-17 via `gh release create v0.15.0 --latest` (cut from the
> CHANGELOG `[0.15.0]` section, 2026-10-17).

The structured error surface release: Wise's error envelope is no longer
discarded. Non-2xx responses now carry Wise's granular, machine-readable
error codes three ways — the structured `APIError.Details` envelope, eleven
wrap-proof `errors.Is` code sentinels, and the open-enum `APIError.HasCode`
matcher — plus a central named error catalog and a first-class
`*BadRequestError` for HTTP 400s. No new endpoints and no signature changes:
46 client methods across 17 resources, same as v0.14.0.

## Highlights

- **`APIError.Details`** — the structured wire envelope
  (`errors[].code` / `errors[].message`) is retained on every typed error as
  `[]WiseErrorDetail{Code WiseErrorCode, Message string}` in wire order.
  `Message` keeps its historical flattened join byte-for-byte, so existing
  logs do not change shape.
- **Eleven curated code sentinels** — `errors.Is(err, wise.ErrNotValid)`,
  `ErrResourceNotFound`, `ErrRateLimitExceeded`, and eight more wave-1 codes
  match by value through any `fmt.Errorf("%w")` wrap chain and through every
  typed subtype. The match compares structured `Details` codes only — never
  message text, never type identity.
- **`APIError.HasCode`** — any other granular code branches through the open
  enum `WiseErrorCode` (14 documented constants from a spec census; unknown
  wire values pass through unmodified). `HasCode` and `Details` are promoted
  onto every typed error: extract the type your HTTP status maps to and call
  them there.
- **`*BadRequestError`** — HTTP 400s are now a first-class typed error
  (`wise.bad_request`, Rejection family, non-retryable) instead of a bare
  `*APIError`; Wise's granular reason codes arrive in `Details`. This is the
  one breaking change — see Compatibility.
- **Central named error catalog** (`errors.go`) — every error code the SDK
  emits is a named constant (51 domain codes alongside the seven typed-error
  codes), and the four response-shape sentinels are exported and always
  returned wrapped (`ErrEmptyRateList`, `ErrAccountIdentificationCardinality`,
  `ErrOTTAlternativesShape`, `ErrTransferRefundAmountMissing`), so
  `errors.Is` reaches them through production wrap chains.
- **`docs/error-codes.md`** — a reference for every granular code: sentinel,
  typical HTTP status, retry guidance, and matching recipes. The README
  error-handling section teaches the same story as a three-step decision
  tree.
- **Platform checks** — `checks.anchor-check` (living-docs line anchors),
  `checks.linter-allowlist` (curated golangci list as a gate),
  `checks.script-fixtures` (negative fixtures for the pin-sync and
  spec-drift scripts), a network `pin-sync` CI job, and the
  `docs/bench/2026-10-16_v0140_baseline.txt` benchstat baseline.

## Compatibility

One breaking change, with a mechanical migration (full table in the
CHANGELOG):

**400s are now `*BadRequestError`.** Code that extracted
`errors.AsType[*wise.APIError]` to handle a 400 must extract
`errors.AsType[*wise.BadRequestError]` instead. The promoted surface is
identical (`StatusCode`, `Message`, `Body`, `Headers`, `Details`, `HasCode`,
`ErrorContext`), so the handler body does not change:

```go
// Before (v0.14.0): a 400 arrived here.
if apiErr, ok := errors.AsType[*wise.APIError](err); ok {
    fmt.Println(apiErr.StatusCode)
}

// After (v0.15.0): 400s are a distinct type; the promoted surface is the same.
if br, ok := errors.AsType[*wise.BadRequestError](err); ok {
    fmt.Println(br.StatusCode, br.Details)
}
```

Where a curated sentinel exists, prefer the wrap-proof value match, which is
independent of the type split:

```go
if errors.Is(err, wise.ErrNotValid) {
    fmt.Println("wise rejected a value; fix the request, do not retry")
}
```

Everything else is additive: `Details`, the sentinels, `HasCode`, the
catalog constants, and the documentation. Every other status's error type is
unchanged, all endpoint signatures are unchanged, and the flattened error
`Message` is byte-for-byte identical.

## Verification

Every error-shape claim in this release is pinned in-repo:
`TestErrorSurfaceMappingMatrix` (status → type + code → match, end to end
against the mock harnesses), fuzz invariants over the envelope join, the
sentinel contract tests (`TestSentinelsStayInterfaceTyped`,
`TestSentinelsMatchThroughProductionWraps`,
`TestAsTypeAndIsAreComplementary`), and the conformance gate against the
vendored OpenAPI snapshot.
