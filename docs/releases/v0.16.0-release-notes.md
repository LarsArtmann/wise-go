# wise-go v0.16.0

The sandbox-verification release: the SDK's SCA and error contracts are now
pinned against the live Wise sandbox, and the one-time-token surface rolls to
the current quarter. 46 client methods across 17 resources, same as v0.15.0 —
no signature changes.

## Highlights

- **OTT surface rolled 2026Q3 → 2026Q4** — the SCA one-time-token endpoints
  now call `/2026Q4/one-time-token/...`. Live-verified with data on the new
  prefix: an SCA-raised token resolves through `GetOTTStatus` with the
  statement action, a bounded validity window, and the pending SIGNATURE
  challenge. No wire-shape change; the served window spans 2026Q2..2027Q1.
- **Five spec-vs-live assumptions settled** by the first credentialed
  sandbox pass: the `/v1/rates` array shape and the funding-error contract
  are VERIFIED, the statement `type` COMPACT/FLAT contract and the
  `details.type` enum are SCA-gated behind a SIGNATURE challenge (partial),
  and `X-idempotence-uuid` balance creation is VERIFIED — creation
  round-trips for standard and savings balances and an identical
  idempotency key replay returns the already-created balance.
- **Permanent key-gated sandbox live tests** (`sandbox_live_test.go`):
  exchange-rate shape, typed funding-404, the SCA challenge wire contract,
  the OTT status lifecycle, and CreateBalance idempotency. They run only
  when `WISE_SANDBOX_API_KEY` is set; keyless runs skip cleanly.
- **`Quote` residual fields** — `PreferredPayIn` (typed `PayIn`),
  `RateExpirationTime` (`time.Time`, optional), `TargetAmountAllowed`
  (`bool`), and `User` (typed `UserID`) now surface from the quote schema.
- **Live-only wire shapes documented** (`docs/error-codes.md`): the
  top-level-`code`-only error envelope and the router-shaped quarterly-surface
  404, plus the funding-404 `application/json` content-type fact.

## Compatibility

No breaking changes. The OTT prefix flip changes request URLs only — the
endpoints, signatures, and wire shapes are identical on the new quarter.
The `Quote` additions are new fields on an existing struct. Existing
consumers compile and behave unchanged.

## Verification

Every lane claim is pinned by the new live tests (credentialed run green
2026-10-17) and the existing gates: the conformance suite against the
vendored OpenAPI snapshot, `nix flake check` (race, coverage floor,
pin-sync, anchor, linter-allowlist, markdown snippet checks), and the
pre-release chain including `apidiff` against v0.15.0.
