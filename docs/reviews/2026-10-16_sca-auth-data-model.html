00Summary

First-principles review of wise-go's SCA domain — the one-time-token (OTT) "lock", the challenge types it demands, and the channels that clear them — run jointly with a go-modularize assessment (UNIX-style boundaries). The domain was already half-right: channel vs challenge type are separate types, enums pass unknown values through, and the OTT secrecy contract holds in every error surface. One critical rot remained: the OTT itself was a bare string, swappable with the OTP code beside it. Companion series: 2026-08-21 v1.0 API audit, 2026-08-08 API docs study.

01Problem catalog

P1 · Critical · fixed

The one-time token was a bare string — swappable with the OTP code beside it

ott.go (pre-change): GetOTTStatus(ctx, ott string) · VerifyOTT(ctx, ott, channel, otpCode string)

The OTT is a credential that authorizes one SCA action; the OTP code is a 6-digit user entry. Both were string, adjacent in VerifyOTT's signature — swapping them compiled. Five public surfaces plus the WithSCAApprovalToken option all took the same undifferentiated string. This is the classic stringly-typed-credential rot (P1/P4).

Fix shipped type OneTimeToken string + validated constructor; all six surfaces typed. The swap is now a compile error.
P4 · Medium · fixed

ActionType was an anonymous string

ott.go: OTTStatus.ActionType string ("BALANCE__GET_STATEMENT")

An open enum modeled as a bare struct-field string — readable but unsearchable and untypeable at boundaries.

Fix shipped type OTTAction string; the field is typed, unknown values still pass through (Wise adds actions).
Docs bug · fixed

README example printed the raw OTT

README.md error-handling example (pre-change): fmt.Printf("... token: %s", sca.TwoFAApprovalToken())

The SDK's own contract says the OTT must never appear in a log — and the flagship example logged it. Every copy-paste of that example carried the leak.

Fix shipped The example now prints only token issued: %t via IsZero().
Contract gap · fixed

Tokenless PSD2 challenges were unpinned on the SDK side

errors.go isSCAChallenge — either 2FA header triggers; no test for result-only

The 2026-10-16 live incident (403 with the verdict header, no OTT) was pinned in bank-sync's adapter, but wise-go itself had no test that a tokenless challenge yields *SCAChallengeError with a zero token and approval_token_issued=false.

Fix shipped TestCheckErrorTokenlessSCAChallenge pins the contract.
Kept · decision logged

Three deliberate keeps (not rot)

ott.go: OTTChallengeView.ViewData · OTTStatus.Validity · absent SCA-session type

ViewData map[string]any: Wise documents the attributes as open-ended ("messages, IDs, or other attributes") — a typed struct would fake precision the wire does not promise. Validity as duration, no expiry instant: the wire carries seconds; inventing an expiry timestamp requires a clock the SDK does not own (consumers inject clocks). No SCA-session type yet: the 5-minute session endpoint is not implemented (YAGNI until a consumer exists); the concept is documented in the decision log with its trigger.

What was already right (and stayed)

+
Channel vs challenge type are distinct types OTTChannel (lowercase wire paths) and OTTChallengeType (UPPERCASE) never mix; OTTChannel.challengeType() is the single mapping — the 2026-10-05 gotcha made structural.
+
Open enums pass unknown values through Wise adds challenge types; decode never fails on novelty.
+
The OTT secrecy contract holds everywhere Error strings, ErrorContext (issued bool only), and the status mapper's dropped wire echo — the credential never reaches a printable surface.
+
Behavioral methods carry the invariants PendingRequired()/Cleared()/Supports(channel) make the challenge state machine queryable without exposing it.

02The vision — one lock, typed keys

The lock-and-keys model

SCA in Wise is ONE lock (the OTT and its challenge list) with several keys (OTP channels today; PIN / FaceMap / device fingerprints are JOSE-encrypted keys not yet built). The data model says exactly that: a typed credential for the lock, open enums for what it demands, one typed channel axis for the keys we hold. Per-key packages or a separate go.mod would fragment the lock — the seam is documented instead (decision log #4).

OneTimeToken (the credential) ├── OTTChallenge / OTTChallengeType (what Wise demands) ├── OTTChannel (how phone keys satisfy it) ├── OTTStatus (state: pending / cleared) └── JOSE keys (PIN/FaceMap/fingerprint — future module)

03Go data model (as shipped)

// The credential: opaque, secret, zero-value = "no token" (tokenless PSD2 flavor).
type OneTimeToken string

func NewOneTimeToken(value string) (OneTimeToken, error) // rejects blank, never trims
func (t OneTimeToken) IsZero() bool

// What Wise demands (open enum, UPPERCASE wire values).
type OTTChallengeType string // PIN, FACE_MAP, SMS, WHATSAPP, VOICE, PARTNER_DEVICE_FINGERPRINT

// The action a cleared token authorizes (open enum).
type OTTAction string // e.g. BALANCE__GET_STATEMENT

// The state machine (unchanged shape, typed field):
type OTTStatus struct {
    Challenges []OTTChallenge
    Validity   time.Duration
    ActionType OTTAction
    UserID     UserID // branded
}
func (s *OTTStatus) PendingRequired() []OTTChallenge
func (s *OTTStatus) Cleared() bool

// The transport header constants stay the wire contract:
const HeaderOneTimeToken = "One-Time-Token" // requests to the OTT endpoints
// x-2fa-approval / x-2fa-approval-result: response side (SCAChallengeError)

Validation layer — invalid states unrepresentable

Three compile-time and one runtime gate

Compile-time: an OTT cannot be passed where an OTP code, an API key, or a correlation ID is expected (type mismatch); an OTTChannel cannot be compared to an OTTChallengeType; ActionType boundaries carry the named type. Runtime: NewOneTimeToken rejects blank input as a Rejection (never trims — an opaque credential must not be silently mutated), and the endpoint methods guard IsZero before any request.

05Decision log (with rejected alternatives)

D1 · newtype of string, not a struct

OneTimeToken is type OneTimeToken string

Rejected: struct{value string} with an Expose() accessor

A struct would hide the value from accidental printing — but the SDK's secrecy contract is already behavioral (errors never carry it), a string newtype keeps comparisons and untyped-constant call sites compiling, and bank-sync's own SCAApprovalToken wrapper owns the Expose discipline at its boundary. No String() method was added: fmt sugar for a secret is a footgun.

D2 · OTP code stays a string

Only the credential is typed, not the user's keystrokes

Rejected: type OTPCode string

The swap risk is killed once ONE side of the pair is typed. The OTP code is ephemeral user input validated at the endpoint (empty check); typing it adds ceremony without preventing any remaining confusion.

D3 · API key is transport, not a peer factor

wise.New(apiKey) stays the constructor

Rejected: an auth package per "way to authenticate"

The API-key Bearer token and the OTT header travel on the SAME requests (setHeaders) — separating them into packages would break the client for zero composability. The API key IS the transport every factor rides.

D4 · modularize verdict: defer, with triggers

No new go.mod today; the JOSE split has a documented trigger

go-modularize scoring: 1 High (2 packages, single domain) + 1 Medium (one real consumer) → partial only

A wise-go/sca module today fails the litmus: every consumer imports it together with the client (no composability payoff — FM#8), and the endpoints are Client methods, so a module split drags the HTTP machinery with it. Trigger: when a JOSE factor (PIN / FaceMap / fingerprint verify — all application/jose+json) is actually built, extract wise-go/sca-jose so go-jose stays out of every API-key+OTP consumer's graph. That split has real payoff; today's would be ceremony. Recorded in ROADMAP alongside the SCA-session endpoint decision.

Anti-patterns to avoid

Traps around the new model

Never add String() or Expose() sugar to OneTimeToken in this SDK; never compare an OTTChannel to an OTTChallengeType (the mapping is challengeType(), nothing else); never trim a OneTimeToken (blank → reject, not repair); never cache an OTT past OTTStatus.Validity (3600s typ.) — it is single-purpose and short-lived by design.
