## 3. Breaking-change risk register (what v1.0 freezes)

Ranked by likelihood a future change breaks consumers:

1. **Struct field sets of result types** — ADDING fields is safe; RENAMING/REMOVING breaks struct literals and field access. Highest-usage fields: `Transfer.Status/Source/Target`, `Quote.PaymentOptions`, `Transaction.Amount/Total`. Risk: Wise adding wire fields → we add struct fields (safe). Verdict: freeze names now.
2. **Method signatures** — 31 methods. Any parameter change is breaking. Variadic-option patterns were deliberately avoided in favor of request structs where growth is plausible (`QuoteAccountRequirementsRequest`, `GetStatementRequest`). Methods with bare ID params (`FundTransfer(ctx, ProfileID, TransferID)`, `GetBalance`, `CancelTransfer`) are simple enough to be stable; growth needs would go through new methods.
3. **Error type hierarchy** — `APIError` embedded in all subtypes; consumers use `errors.AsType[*wise.RateLimitError]`. Changing embedding or adding new subtypes is additive-safe; REMOVING a subtype breaks `errors.AsType` calls. Freeze the six.
4. **Branded ID underlying types** — `QuoteID`/`TransactionID` are string-branded; the rest int64. A future flip would break `.Get()` arithmetic. Freeze.
5. **Enum string values** — constants mirror Wise's wire values; can only grow (documented pass-through). Safe by design.
6. **`Doer` interface** — consumed by `WithHTTPClient`. Matches `http.RoundTripper`-adjacent shape; stable.
7. **Behavioral contracts worth documenting as frozen**: cents-based `Money` (no float returns), UTC timestamp normalization (zoneless→UTC in, `Z` out), Corruption-classified mappers, Rejection-classified client-side validation, retry exhaustion surfacing the final attempt's typed error.

**Recommendation:** the surface is coherent and completely godoc'd; nothing identified blocks the v1.0 tag. The tag remains gated on the user's explicit approval (plan task 25) — this report is the prerequisite input.
