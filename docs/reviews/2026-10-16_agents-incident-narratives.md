Point-in-time evidence for the constraint stubs in AGENTS.md. The stubs carry
every live constraint; this file carries the WHY and the full history so a

M24 AGENTS prune (21:45 plan T85-T86).

- **branching-flow panic: two suppressed false positives in webhooks.go** — `ListProfileWebhookSubscriptions` dereferences `*mapped` and `decodeWebhookEvent` dereferences `*payload`; both helpers provably never return `(nil, nil)` (the only non-error return is `&struct{...}, nil`), but the analyzer has no interprocedural/generics tracking. Suppressed via trailing `//nolint:branching-flow:panic` + rationale, with two placement constraints both verified 2026-10-05: (1) the directive must trail the DEREFERENCE line itself (`*mapped,` / `raw.WebhookOccurredAt(*payload),`) — placing it on the enclosing call's closing paren suppresses nothing; (2) the line must fit golines' 120 cols (tab=4), so keep the rationale short. nolintlint rejects the colon-syntax directive as "unknown linter" — coexist via the `.golangci.yml` `linters.exclusions.rules` source-rule (`//nolint:branching-flow:`), not per-line nolint. Do not add nil checks.
**go-auto-upgrade samber/lo + jsonv1tov2 findings are deliberate non-fixes** — every run flags sites (manual `for`-range Map/Filter loops in currencies.go, ott.go, quotes.go, transfer_requirements.go, errors.go, recipients.go, …) suggesting `samber/lo`: DECLINED, re-ruled with a full census 2026-10-07 (all 9 sites individually reviewed: 6 idiomatic keeps incl. a prepend-cons the Map pattern over-matches and a keyed map transform lo.Map can't express, 3 marginal lo.Map fits, 0 decisive; fleet adoption 34/322 repos = no standardization pressure). The SDK is deliberately dependency-light (two runtime deps, both in-house; ADR 003 dropped failsafe-go for exactly this reason) — a third-party dep in every consumer's graph for 3-line-loop sugar is the wrong trade. The 9 `go-version-required` findings are the jsonv1tov2 migration correctly REFUSING to run on the pinned go 1.26. Both classes are warning/info severity, below the error-level findings gate — a green buildflow exit with them present is correct, do not add the dep or skip the step to silence them.
**strong-id analysis has deliberate non-fixes** — `branching-flow strong-id` re-flags the same sites every run; do not "fix" these: all `internal/raw` fields stay wire primitives (two-layer design), `WebhookResource.ID`/`.AccountID` are polymorphic ID spaces (transfer vs balance vs recipient-account depending on event type — spec descriptions differ per schema), `WebhookCreator.ID`/`WebhookScope.ID` are application-key vs user/profile discriminated by Type/Domain, `Profile.PublicID` is an opaque reference never sent to the API, and correlation IDs are tracing metadata, not entity IDs (branding would break the `WithCorrelationID`/`WithRequestCorrelationID` signatures for no compile-time gain). Implemented 2026-10-05: `CustomerTransactionID` brand (Transfer + CreateTransferRequest + ValidateTransferRequirementsRequest, guarded via `requireID`) and `OTTStatus.UserID` / `WebhookResource.ProfileID` on the existing UserID/ProfileID brands.
**erraudit `--enforce-generic-return` findings are deliberate non-fixes** — the flag is OFF by default and erraudit's own help says "returning error is standard Go practice"; enabling it flags every bare-`error` return: full census 2026-10-16 = 55 findings (41 exported client methods + 14 unexported helpers/mappers: getRaw, request, doRequest, executeWithLogging, fetchByID, quoteAccountRequirements, decodeExchangeRates, listRecipientsPage, mapBalance, mapTransaction, mapExchange, listTransfersPage, toTransfer, mapTransfer). DECLINED as a class: each method's error surface is a UNION (`*APIError` + `*AuthError`/`*NotFoundError`/`*RateLimitError`/`*SCAChallengeError`/`*ServerError` via `newAPIError`, go-retry exhaustion chains, validation Rejections, corruption wraps) — a per-method concrete `XxxError` would either wrap that union as a pointless extra layer or make the signature lie; consumers inspect via `errors.AsType[*wise.RateLimitError]` (pinned by the retry-exhaustion convention), which requires `error` interface returns; and 41 exported signature changes would break every consumer pre-v1.0 for zero new capability. The canonical gate stays `erraudit lint ./... --type-aware --enforce-coded-errors` (exit 0, re-verified 2026-10-16); the other enforcement flags (`--enforce-go-error-family`, `--enforce-samber-oops`, `--enforce-deferred-close`, `--no-suppress`) were verified 0-finding clean the same day and could be adopted into the gate later without noise. Also: `erraudit tree` reporting "4 errors · 0 relationships" IS the complete static picture — the SDK has exactly 4 package-level sentinels (account-identification cardinality, empty rate list, OTT alternatives shape, webhook refund amount missing — exported + centralized into errors.go the same day), each with exactly 1 wrap site; the remaining ~130 inline wrap sites wrap unnamed runtime errors (the APIError family) that cannot become hierarchy edges by design (`--inline-wraps` renders them as leaf annotations only).
**LSP phantoms were an env problem, root-caused 2026-10-07** — the LSP servers (gopls AND golangci_lint_ls) are launched by Crush OUTSIDE the nix devShell, so they lacked `GOEXPERIMENT=jsonv2`; the repo imports `encoding/json/v2` (via go-branded-id/go-error-family) whose stdlib files are build-constraint-excluded without it, so the package load FAILED and both servers produced phantom diagnostics: gopls false `bytes imported and not used` (internal_test.go:4), `undefined: json`, and golangci's "File is not properly formatted" on webhooks.go:142. Verified by A/B: `env -u GOEXPERIMENT gopls check internal_test.go` reproduces the import failure; with the var set, the package loads. Fix: project-local `.crushrc` redeclares both LSPs with `--env GOEXPERIMENT jsonv2` (activates at session start; cleared the poisoned golangci analysis cache via trash). `stdversion` stays disabled in the LSP config: with the experiment ON, `gopls check` flags json/v2 usage as "requires go1.27 or later" under the 1.26 pin while the suite compiles and passes — do not "fix" those findings by migrating json/v2 call sites early; that is the Go 1.27 plan's job. Any recurrence of these phantoms after 2026-10-07 means the env fix stopped applying — check `.crushrc` survived and `go env GOEXPERIMENT` inside the server env.
**buildflow warning-class findings are pre-dispositioned (2026-10-11) — do not re-triage** — statix's "repeated keys" (2 real findings; buildflow's "27" counts rendered output LINES, not findings) is the deliberate dotted-assignment style in flake.nix (`checks.test = ...; apps.apidiff = ...`), idiomatic Nix, do not restyle. vulnix's ~22 advisories are all pinned-nixpkgs toolchain drvs (binutils/gcc/bison/coreutils), build-time only; the lever is a scheduled `nix flake update nixpkgs`, not repo code. markdownlint stays on-demand and UNWIRED: default MD013 line-length fights the repo's long-line markdown style, and dprint owns markdown formatting. The pipeline's "9 tools unavailable" summary is an upstream display artifact — on-demand tools count as unavailable even when installed; ground truth is `buildflow doctor` (failures dropped 30→28 when gitleaks/codespell/markdownlint joined the devShell) or a direct `buildflow -s <tool>` run. gitleaks needs `.gitleaks.toml` (allowlist for the vendored OpenAPI spec's documentation fixtures: example tokens/keys/JWTs, 30 false positives) and codespell needs `.codespellrc` (`unparseable` is the repo's deliberate spelling; `docs/reviews/*` and `docs/status/*` are historical/vendored and skipped) — both verified clean 2026-10-11; delete either config only with a replacement disposition.
