## b) PARTIALLY DONE

1. **The hermetic `checks.pin-sync` is weaker than its name implies.** It cannot
   compare a pinned `?rev=` against the `go.mod` version offline — there is no
   tag→commit map without network. So the _hermetic_ check catches:
   non-immutable pins, `flake.lock`≠`flake.nix`, and tag≠version — but **NOT a
   stale rev after a `go get` bump**. That drift is only caught by
   `apps.pin-sync` (network), i.e. only when `pre-release` runs. `nix flake
   check` alone (and any future offline CI) would have missed the very bug we
   fixed. **This is the most important partial item.**
2. **`pin-sync` is wired into `pre-release` but not into `.github/workflows/ci.yml`** —
   CI is disabled, so this is deferred, not forgotten.
3. **Version mentions not fully propagated** — README + `types.go` updated;
   FEATURES.md / ROADMAP.md still narrate the surface "as of v0.12.0" and the
   ROADMAP shipped-list does not mention v0.13.0. Arguably fine (historical),
   but the living docs now lag one release.
4. **(f) items not harvested** — the status-report skill's HARVEST step (push
   section (f) into `TODO_LIST.md`/`ROADMAP.md`) was **not** run; you asked me to
   wait.
5. **No negative test for pin-sync.** The two detectors in
   `release-notes-check` had crafted-bad negative tests; `pin_sync.py` has
   none. A regression in the parser would silently pass.
6. **The `deps` map in `flake.nix` is not cross-checked** — pin-sync verifies
   `go.mod`↔flake input, but `go-standard.deps` (module path → input) is a third
   place the mapping lives; a mismatch there is unchecked.
7. **`scripts/pin_sync.py` has no unit tests** and is not part of any
   `nix flake check` beyond the `pin-sync` check itself.
8. **Coverage was not re-measured** — 93.1% is carried from the prior session;
   the gate enforces ≥90 so ≥90 is proven, but the headline number is stale.
9. **`many examples` / doc-verify "25 Example funcs"** — verified, but the
   90→92 coverage-floor bump (TODO) was left undone.

## e) WHAT WE SHOULD IMPROVE

1. **Make drift detection hermetic.** The clean fix is to pin the in-house Go
   deps by **version tag** in the flake URL (`github:LarsArtmann/go-retry/v0.7.1`)
   and let `flake.lock` pin the immutable commit. Then the offline check can
   compare the tag literal to `go.mod` with no network, and the network app
   becomes belt-and-braces. This is the single highest-value follow-up.
2. **Negative-test every gate.** Add a crafted "stale pin" fixture for
   `pin_sync.py` (and a unit test), mirroring the `release-notes-check` practice.
3. **Serialize the daemon during a release.** Either pause the auto-commit
   daemon, or do the release as a single `git commit`/`git tag` immediately after
   `pre-release` with the tree otherwise untouched, so history is legible.
4. **Never sweep unknown changes.** When a dirty file is not mine, inspect it
   and either commit it deliberately (with rationale) or leave it — not "fold
   into cleanup".
5. **One source of truth for the version↔pin mapping.** Today it lives in
   `go.mod`, `flake.nix` inputs, and `flake.lock`; pin-sync should validate all
   three plus the `deps` map.
6. **Close the "offline vs online" claim gap** in docs: state plainly that the
   hermetic check is structural and the network app is the real detector.
7. **Harvest (f) into TODO_LIST/ROADMAP** so this report does not become an
   entombed snapshot.
8. **Re-measure coverage fresh** at release and print it in the report.
9. **Propagate the version** to FEATURES.md/ROADMAP.md living-doc narration.
10. **Add a `pin-sync` job to `ci.yml`** when CI re-enables (network job, like
